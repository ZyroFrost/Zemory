# Folder standard — the NON-APP system

> The project is a **PRODUCT / ASSET** (deliverable), with NO running app code. The agent only **reads · searches · pulls · fills · exports FILES** — including opening a `.pbix` to inspect and pouring figures into a template. ⇒ **0 UI rules**.
> Full conventions (naming, numbering, tracked vs gitignore) → [`references/conventions.md`](references/conventions.md). Automatic check → `scripts/check_structure.py`.

## 1. Principles

- Described by **ROLE** — BI / data / docs-only / design apply almost the same structure.
- **ONE name per concern.** Follow another name only when a tool FORCES it (`.pbip`/`.Report`/`.SemanticModel`, dbt `models/`).
- **The tree below is A DICTIONARY TO LOOK UP, NOT a list to create.** Create a folder only when **a real file goes into it**. **NEVER create an empty folder** to "complete the set". A typical non-app project uses only **3–8 slots**.
- **3 roles REQUIRED:** `docs/` · `AGENTS.md` · **≥1 deliverable folder**. NO `backend/`+`frontend/`.

## 2. Folder tree

`★` required · `◆` deliverable (≥1) · `[opt]` created only for a real concern.
Slot names are **lowercase**, several words joined by `_`. Existing file/vendor names **stay as they are** (`TargetAll.xlsx`, `.pbix`, `.Report/`).
**EVERY file/folder name WE give is written in plain ASCII English** — NO local language (with or without diacritics), NO non-ASCII characters; most often broken by case names `tasks/<case>/` and `docs/plan/NN_name.md`. The CONTENT inside follows `Rule_Gate_02_ReaderText` · `Rule_Gate_31_NoBrokenVietnamese` — this rule is only about NAMES. The reason: names get retyped in commands·paths·links, diacritics break with encodings and look-alike characters (Cyrillic `с` vs Latin `c`) make a dead reference nobody can see.

```
<project>/
│ ═══ TRACKED — sources + definitions + deliverables ═══
├── AGENTS.md         ★  the entry: project description + loading contract
├── docs/             ★  agent/(01·02·05·06) · plan/ · .harness.json
│       └ 02_STRUCTURE/INDEX.md = slot index generated by the machine · definitions: HP frame Cons_Gate_12_SourceOfTruth
├── docs_visual/      [opt] diagrams · lineage for PEOPLE to view (.html/.svg), OUTSIDE docs/
│ ─── DELIVERABLE — chosen by kind, ≥1 ───
├── reports/          ◆  BI: .pbix/.pbip/.twb                    [LFS when heavy]
├── models/           ◆  data: dbt · tabular .bim · DAX model
├── content/          ◆  docs-only: .md/.mdx is the main product
├── design/           ◆  design: .fig/.sketch/.psd               [LFS]
│ ─── WORK ───
├── tasks/            [opt] cases: SCHEDULE.md + one folder per case <DEPT CODE>_<CADENCE>_<TaskName>/ + spec.md, unnumbered
├── templates/        [opt] EMPTY sample files waiting to be FILLED  (≠ fixtures)
│ ─── INPUT / PROCESSING ───
├── sources/          [opt] source definitions: M · connection spec · pull SQL
├── measures/         [opt] named DAX / formulas + notes
├── queries/          [opt] SQL/DAX/M called by name — NOT scattered inline
├── pipelines/        [opt] <domain>/ ETL shared by several cases · common.py + stages 00,01,02…
├── notebooks/        [opt] exploratory analysis .ipynb
├── fixtures/         [opt] small SAMPLE data (tracked) — opens the deliverable without the real source
├── assets/           [opt] theme · logo · icons · colour table
├── scripts/          [opt] automation: pull · fill · publish (THIN, called by the agent)
├── config/           [opt] connection profiles: *.example.* tracked · real ones → gitignore
├── attic/            [opt] old copies / snapshots BEFORE publishing (rollback) — tracked
│ ═══ ROOT — position forced by a tool, do NOT move ═══
├── README.md · LICENSE · .gitignore · .gitattributes
├── <name>.cmd        [opt] task launcher — **PLAIN ASCII** (Vietnamese diacritics break cmd.exe)
├── .github/ · .vscode/ · .idea/   [opt] left at the root
│ ═══ GITIGNORE — NOT committed ═══
├── data/             [opt] REAL files (heavy/PII): extract/ · adhoc/ · <task>/
├── exports/          [opt] render/publish copies — can be regenerated
└── .env              [opt] REAL connection strings · tokens
```

**The minimal tree:** `AGENTS.md` + `docs/` + **≥1 deliverable**. Every other slot is `[opt]`.

## 3. Routing — what you need / have → where it goes

| What you have / need to do | → Slot |
|---|---|
| a report / model / content / design handed out | `reports/` \| `models/` \| `content/` \| `design/` ◆ |
| **a unit of work** (weekly report, an analysis round) | `tasks/<DEPT CODE>_<CADENCE>_<TaskName>/spec.md`, unnumbered · real data → `data/<case>/` |
| **things of ONE case** (pull SQL · check queries · config · findings) | `tasks/<case>/` — ask first: one case or shared? (slot `Tasks_115_Tasks`) |
| **a pipeline running a task** (numbered stages) | `tasks/<case>/pipeline/` · `common.py` + `00_`/`01_`/`02_`; ETL used by several cases → `pipelines/<domain>/` |
| **the list of recurring work** (cadence + the line pasted into the schedule) | `tasks/SCHEDULE.md` — ONE line per task |
| **a launcher running a task** | `bin/<name>.cmd` — plain ASCII (slot `Bin_082_Bin`) |
| **stage output / deliverable** | intermediate `data/<task>/NN_*` · deliverable with a business name (NO number prefix) |
| **a sample file waiting to be FILLED** (an empty report) | `templates/` |
| **a shared source definition** (M / connection / pull SQL, used by two cases or more) | `sources/` — points to env NAMES, NO real secret |
| named DAX / measures | `measures/` |
| SQL / DAX / M called by name, used by two cases or more | `queries/` — NOT scattered inline |
| multi-step ETL / transforms | `pipelines/` |
| exploratory analysis | `notebooks/` |
| small sample data that opens the deliverable | `fixtures/` (tracked) |
| theme / logo / colour table | `assets/` |
| **automatic PULL / FILL / UPLOAD** | `scripts/` (thin) + skills `pull` · `fill` · `upload` |
| workspace/connection profiles | `config/` — `*.example.*` tracked · real ones gitignored |
| **raw extracts pulled down** (heavy, PII) | `data/extract/` (gitignore) |
| **a loose one-off check file, not part of a task** | `data/adhoc/` (+ README marker) |
| working data of 1 task | `data/<task>/` (gitignore, mirrors `tasks/`) |
| generated render/publish copies | `exports/` (gitignore) |
| REAL connection strings / tokens | `.env` (gitignore) |
| metric/column definitions (the source of truth) | HP frame `Cons_Gate_12_SourceOfTruth` (section Definitions) · how to compute: a skill of its own `Skill_Own_<Name>` |
| flow/lineage diagrams to view | `docs_visual/` — OUTSIDE `docs/`, with an owning `.md` pointing to it |
| old deliverable copies / before publishing | `attic/` |
| documents / laws / plans | `docs/` — edit the `.md` file directly (file wins) |
| a repeated operating procedure | `.claude/skills/<name>/SKILL.md` |

## 4. Before creating or moving anything

1. Look up the §3 table → get the slot. No line matches → **ASK**, do not invent a new name.
2. Compare with [`references/conventions.md`](references/conventions.md) for naming and numbering conventions.
3. **Moving existing files = a PROPOSAL, not done alone.** Print the table `file/group · sits in · should be in · why`, wait for a nod on each item. Reshaping a whole folder → the `reconcile` skill.
4. Adding a new slot to the standard = **changing the standard** → follow §5, present it for approval first.

## 5. Proposing a new slot or template

1. Write down the path and the file type of the thing needing a place.
2. Search EVERY slot on HS by **path** (a duplicate · inside a slot's folder) and by **file type** (the same role under another
   name: `package.json` · `pyproject.toml` · `requirements.txt` are all dependency declaration files). A slot name is not the search.
3. An existing slot can take it ⇒ widen its `path:`, or add that slot to the template needing it. Do not create a new slot.
4. The content is a shared standard (laws, procedures, frames) ⇒ break it into the matching HS part, do not keep it as a folder of the repo.
5. Only when the thing has **its own rule** the old slot lacks (which templates may have it · who may edit · whether it enters git) ⇒ a new
   slot: header `checked: [<slot weighed>, …]`, the body has a line `Khác <old slot>: <own rule>` for each slot it overlaps.
6. A new structure template: search the `Struc_*` the same way; an existing template that can take another slot or `role` ⇒ edit that template.
7. The proposal goes through `Rule_Gate_85_ProposeChecked` and `Rule_Gate_83_HarnessFromStore`.

- Example ✗: slot `Root_142_Requirements` for `requirements.txt` and `Content_141_WorkspaceStandard` for the shared standard-set folder.
- Example ✓: add `requirements.txt` to the `path:` of `Root_059_PackageJson`; break the shared standard-set folder into laws and skills on HS.
- Machine check: the gate goes red when a new slot overlaps an old one without `checked:` or without the `Khác` line.
